# Guard access recovery and shared-phone procedure

Use this procedure when a guard cannot sign in on a shared phone.

1. Confirm the guard’s identity using the customer-approved roster and their supervisor.
2. A supervisor or owner resets access through the Users screen. Do not reuse another guard’s account.
3. Tell the guard to sign in using the new credential. Pending work remains encrypted under the old credential on that same browser and cannot be recovered with the new credential.
4. If pending evidence matters, keep the original session/credential available long enough to upload it, or record the limitation in the shift exception log. Do not delete browser storage in an attempt to recover it.
5. If the phone is lost, immediately disable the account. This revokes active sessions. Close any stranded shift through the audited exception-close action and record the reason.

This is an assisted pilot procedure. It does not claim that encrypted work can be recovered after credentials or browser storage are lost.
